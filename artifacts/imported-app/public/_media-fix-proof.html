v0.7.186 — Media flow restore (echo · freeze · VU meter)

Operator complaints addressed: (1) preview keeps playing audio when the same media goes live → echo; (2) audio indicator on the preview pane stays at zero; (3) preview frame keeps ticking instead of freezing.

ROOT CAUSE
v0.7.158 switched the Preview pane from a React <video> renderer to an iframe of /api/output/congregation. Verses now match the projector exactly, but media broke in three ways: (a) the React-side shouldBePaused = globalIsLive || mediaPaused rule never reached inside the iframe, (b) the previewVideoPlaying + audioLevelPreview store flags that drive the green VU meter were written by the now-unmounted MediaSlideContent useEffects, (c) the iframe video kept playing audio in parallel with the live iframe → echo.

How the fix works (architecture)

┌────────────────────── Preview pane (logos-shell.tsx PreviewCard) ──────────────────────┐ │ │ │ VISIBLE ┌──────────────────────────────────┐ │ │ │ <OutputPreview │ ◄── slideOverride={effectivePreviewSlide} │ │ │ iframe(/api/output/...) │ (cloned with mediaPaused:true │ │ │ -- the SOLE audible source │ when same media is on Live) │ │ │ /> │ │ │ └──────────────────────────────────┘ │ │ │ │ HIDDEN ┌──────────────────────────────────┐ │ │ (1×1px, │ <HiddenMediaMeter │ ◄── attachAnalyserSilent() — does NOT │ │ off- │ src={previewSlide.mediaUrl} │ connect to AudioContext.destination, │ │ screen) │ paused={previewMediaIsLive} │ so this element produces ZERO sound. │ │ │ /> │ Analyser still reads the RMS so the │ │ │ │ green meter has a real signal. │ │ │ v.muted = false (must be — │ │ │ │ muting the HTMLMediaElement │ │ │ │ silences MediaElementSource │ │ │ │ too) │ │ │ └──────────────────────────────────┘ │ │ │ │ FLAGS WRITTEN BY HIDDEN VIDEO → audioLevelPreview · previewVideoPlaying │ │ READ BY THE GREEN VU METER → AudioMeter at logos-shell.tsx L837 │ │ │ └────────────────────────────────────────────────────────────────────────────────────────┘
Why one source = no echo
Once a media element is captured by createMediaElementSource(el) the browser replaces its native audio path with the Web Audio graph. If the graph never reaches AudioContext.destination, the element produces no sound at all — but the analyser still sees the decoded RMS. The hidden React video is therefore audibly silent yet metrically alive. The visible iframe stays the only audible source for the preview pane, exactly like the v0.7.157-and-earlier behaviour.
Why the freeze is automatic
The iframe renderer (route.ts ~L1048-1126) already pauses any media slide whose payload carries mediaPaused: true. We just splice that flag in only when the previewed mediaUrl matches the live mediaUrl — verses, images and theme slides flow through unchanged.
