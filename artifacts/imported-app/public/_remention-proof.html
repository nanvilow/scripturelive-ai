Root cause

v0.7.184.2 fixed half the bug — only the navigator half.
v0.7.184.2 wired requestNavigatorRef(ref) at all four upstream dedupe gates so re-mentions move the Chapter Navigator. But requestNavigatorRef only updates the navigator search box — it does not push to Live Display. The first-mention path at L2120 calls a separate setLiveVerse(verse) which is what actually sends a verse to ON AIR. The suppress branches never call setLiveVerse, so re-mentions land in the navigator but never on screen.

Operator's complaint maps to this exactly: "the detector doesn't want to drop it again because it's in the column already and doesn't want to auto-send it." → Column dedupe (correct, no dup row) + missing setLiveVerse = stuck Live Display.

Proposed fix — same shape at all 4 dedupe gates

Each gate gets the same 6-line addition: re-fetch verse, set live, add to history. Gated by autoLiveOn so the AUTO toggle still controls behaviour.
// speech-provider.tsx L2088-2099 — Regex-detector explicit branch (representative) for (const detectedRef of detectedRefs) { const ref = detectedRef.reference if (processedRefsRef.current.has(ref) || processedTextHitsRef.current.has(ref)) { try { useAppStore.getState().requestNavigatorRef(ref) } catch { /* defensive */ } // v0.7.186 — RE-MENTION AUTO-LIVE. Same shape as first-mention // L2120 (setLiveVerse + addToVerseHistory) MINUS addDetectedVerse // (column dedupe stays clean → no duplicate row). if (autoLiveOn) { try { const verse = await fetchBibleVerse(ref, state.selectedTranslation) if (verse) { useAppStore.getState().setLiveVerse(verse) useAppStore.getState().addToVerseHistory(verse) } } catch { /* network errors fail open */ } } continue } // … first-mention path unchanged (L2100-2129) }
// Same 6-line addition at the other three gates: // L1572-1574 — Reference Engine v2 (TTL dedupe) // L1817-1819 — Keyword text-search (sticky-live) ← ref text already in scope as `top` // L1975-1985 — AI cosine matcher (3 sets) ← ref already in scope as `m.reference`

Why autoLiveOn gating is correct

When AUTO is OFF the operator manually clicks verses to push them live. In that mode a re-mention should NOT auto-jump — the operator might be on a different slide intentionally. With if (autoLiveOn) wrap, re-mention auto-live mirrors first-mention exactly: both fire when AUTO is on, neither fires when AUTO is off. Symmetric behaviour, no surprises.

What does NOT change

  • Column dedupe (no duplicate "Amos 1:3" row in Verses Live) — preserved.
  • requestNavigatorRef at all 4 gates — preserved (v0.7.184.2 fix stands).
  • First-mention path at L2120 — untouched.
  • Stability gate in logos-shell.tsx (centralized auto-go-live for non-explicit sources) — untouched.
  • addDetectedVerseCandidate (speculative <50%) — never triggers nav OR auto-live (v0.7.182 GR-C preserved).

Guard-rails to add to the v0.7.186 changelog entry

  • GR-A: at every dedupe-suppress branch in speech-provider.tsx, BOTH requestNavigatorRef AND (gated by autoLiveOn) setLiveVerse + addToVerseHistory MUST fire. Either alone is incomplete: nav-only = navigator updates but Live Display stuck (v0.7.184.2 bug); live-only = ON AIR jumps but operator's search box stays out of sync.
  • GR-B: the suppress branch MUST NOT call addDetectedVerse — that was the v0.7.119 column-dedupe and re-introducing it gives duplicate rows in the Verses Live column (visible in operator screenshot).
  • GR-C: any NEW dedupe gate MUST wire all three calls (nav + setLiveVerse + addToVerseHistory).
