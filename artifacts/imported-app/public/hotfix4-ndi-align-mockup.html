v0.7.194-hotfix.4 — NDI Align dropdown actually applies to the lower-third

Operator picks NDI Typography → Align → Justify on the lower-third NDI feed. The store writes ndiTextAlign:'justify' correctly and the renderer's T_TA variable computes 'justify' correctly (route.ts L1217). But the actual alignClass applied to the .lt-box at L1560 reads st.textAlign — the Live Display alignment — completely ignoring the NDI override. Result: operator picks any align value, lower-third stays centered. Dead option. Same bug shape in the full-screen branch at L1662 where ta=st.textAlign||'center'.

The fix (2 lines, route.ts only)

A. Lower-third branch (L1560): 
- var alignClass='align-'+(st.textAlign||'center');
+ var alignClass='align-'+(T_TA||'center');
B. Full-screen branch (L1662): 
- var ta=st.textAlign||'center';
+ var ta=T_TA||'center';
T_TA already cascades correctly for all three contexts (NDI override → LT override → body), so when !IS_NDI && !USE_LT_OVERRIDES, T_TA resolves to st.textAlign automatically — non-NDI surfaces (in-room projector, Live Display, secondary screen) get identical behavior to today. Pure NDI-only effect.

About Size — wired correctly, perception fixed by bundled fix #4

The Size dropdown is wired end-to-end (ndiFontSize → T_FS → scale → ltBand → ltFs). The reason it feels dead today:
  • NDI_DEFAULTS.fontSize = 'xl' (route.ts L1147), so "Mirror Live" baseline already renders at xl.
  • Operator picks "xl" from dropdown → same value → no visible change → looks dead.
  • Picking sm/md/lg does shrink (FS_MULT: sm 0.85, md 1.0, lg 1.25, xl 1.5), but compound auto-fit clamps absorb 50%+ of the bucket delta on long verses.
Approved fix #4 already addresses this — it removes __inherit__ entirely and shows xl as the concrete starting value. Operator then picks md or sm and sees an obvious shrink. No code change needed for Size on top of fix #4.

Why this won't destroy NDI lower-third

  • Same surface, same CSS classes. .align-justify / .align-left / .align-right / .align-center already exist in the stylesheet (L189-192). The bar geometry, transparency toggle, bg image, drop shadow, font family, fps capture — none of it touches alignment.
  • T_TA falls back to st.textAlign in non-NDI paths. So in-room projector + Live Display + secondary screen all render identically to today.
  • Default behavior unchanged. NDI_DEFAULTS.textAlign='center' so existing installs that never opened the NDI Align dropdown stay centered exactly like before.
  • Two-line change. No new state, no new rendering paths, no new event hookups.
Scope of this fix: NDI Align dropdown becomes functional for both lower-third AND full-screen NDI modes. Size dropdown becomes obviously functional after fix #4's __inherit__ removal. No other knobs touched.
