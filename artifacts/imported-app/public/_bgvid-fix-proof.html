v0.7.187 — Bible-verse background video: lag & freeze fix

Operator complaint: "When users upload video for Bible verse backgrounds, it freezes a lot; it's not smooth." Diagnosis & fix below — ships as a single architectural change in route.ts; no other surface code touched.

ROOT CAUSE — one line
The renderer reassigns $('output').innerHTML = '...' on every store update — every speech tick, every settings nudge, every verse navigation. Because the background <video class="bg-image"> was inlined inside that HTML, the entire video element was destroyed and re-created several times per second. Each re-create restarts the file from currentTime = 0 with a fresh network fetch & decoder warm-up → constant juddering across all 6 surfaces (preview, Live Display, secondary screen, NDI, projector, OBS).
Why foreground media DIDN'T have this problem
route.ts already protects foreground media (clips sent live) via the setVid() cache pattern (~L1156): a module-level __liveVideoEl keyed by mediaUrl that REUSES the same <video> element across renders instead of rebuilding it. The same protection was simply never written for the BG layer. Three sites built BG video HTML inline (themed-only branch, verse-render branch, lower-third branch) and all three got nuked on every render.

Architecture (the only change)

┌─── BEFORE — fragile (every render destroys the video) ─────────────────┐ ┌─── AFTER — persistent (survives every render) ─────────────────────┐ │ │ │ │ │ <div id="stage"> │ │ <div id="stage"> │ │ <div id="output"> ← innerHTML reassigned on every tick │ │ <div id="bgLayer"> ← NEVER touched by output.innerHTML │ │ <div class="theme"> │ │ <video src=bg.mp4> ← cached in __bgUrl, reused if same url │ │ <video src=bg.mp4> ← ❌ destroyed + recreated 4-6×/sec │ │ </div> │ │ <div class="bg-overlay"/> │ │ <div id="output"> ← innerHTML still reassigned (verses, etc) │ │ <div class="slide-content">…verse…</div> │ │ <div class="theme" style="background:transparent"> │ │ </div> │ │ <div class="bg-overlay"/> ← still inline (cheap, no decode) │ │ </div> │ │ <div class="slide-content">…verse…</div> │ │ </div> │ │ </div> │ │ │ │ </div> │ │ │ │ </div> │ └───────────────────────────────────────────────────────────────────────┘ └──────────────────────────────────────────────────────────────────────────────┘ setBgVid(url) — module-level, keyed by URL: • same URL → return immediately (no DOM work, video keeps playing) • new URL → release old element (pause + load) + mount new one (hard cut, instant) • '' (empty)→ clear layer (used in blanked / clear / NDI alpha-key / foreground-media branches) Z-index: #bgLayer = 0 (behind) #output = 1 (slide content, overlay) Sizing: #bgLayer mirrors #output's ratio class (16:9 / 4:3 / 21:9) so the bg fills the same letterboxed inner area — never leaks into the surround.
Audio meter — confirmed already correct (v0.7.186)
Operator's other ask: "audio indicator should match the sound coming out of the media. When nothing is playing, the audio indicator should not indicate. Indicate when media with sound is playing and indicate according to the sounds."

v0.7.186's HiddenMediaMeter already does exactly this: Web Audio analyser reads the real RMS of the decoded audio track → meter height tracks loudness in real time; v.paused || v.ended forces 0; videos with no audio track → RMS = 0 → flat zero. No additional change needed for v0.7.187.
What stays untouched (safety scope)
• Image backgrounds: the inline <img class="bg-image"> path was kept in spirit but also routed through the persistent layer for uniformity — images don't have the freeze problem (no currentTime) but the unified path means one less branch to maintain.
• Lower-third backgrounds (.lt-bg at L1359): inline tag retained — that video lives inside the chyron card, not behind it, so the persistent-layer architecture doesn't apply. Operator has not reported lag there.
• Foreground media slides (clips sent live): setVid() cache from v0.7.0 untouched. New setBgVid('') call clears the BG layer when foreground media takes the surface.
• NDI alpha-key (FORCE_TRANSPARENT): setBgVid('') wired so vMix/OBS still receive a clean alpha frame.
• Blanked / type:'clear' / no slide: setBgVid('') wired so the BG layer doesn't outlive its slide.
• Foreground media meter (v0.7.186 HiddenMediaMeter): no change.
