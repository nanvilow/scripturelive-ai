OBS Browser Source URL → NDI Settings v0.7.178 fix

Per operator's two annotated screenshots (postimg CnC4zrNG + VdrfPyKv): make the OBS Browser Source URL pull settings from the NDI pile (not the in-app Lower Third pile or Live Display pile). Fix is one-line per URL builder, plus extensive inline guard-rail comments.

BEFORE (v0.7.177 and earlier)
http://127.0.0.1:47330/api/output/congregation?transparent=1
Route resolves: IS_NDI = false
→ USE_NDI_OVERRIDES = false (NDI typography pile ignored)
→ in Lower-Third mode: pulls lowerThird* pile (in-app LT settings)
→ in Full mode: pulls body settings (fontSize, fontFamily, …)
Result: OBS feed silently differs from NDI Live Preview.
AFTER (v0.7.178)
http://127.0.0.1:47330/api/output/congregation?ndi=1&transparent=1
Route resolves: IS_NDI = true
→ USE_NDI_OVERRIDES = true (NDI typography pile wins on every slot)
→ display mode reads ndiDisplayMode (Full / Lower Third toggle)
→ USE_LT_OVERRIDES = !IS_NDI && … = false — in-app LT pile cannot bleed in.
Result: OBS feed = NDI broadcast, byte-for-byte.
