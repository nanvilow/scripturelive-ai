# Imported App

A Next.js application providing scripture-related services for web and desktop, enhancing live service experiences, and streamlining administrative tasks.

## User preferences

-   **Autonomy**: Act without asking for consent on routine decisions — always do what's better for the app. Do not ask permission for housekeeping (file trims, refactors, retry logic, dependency bumps, replit.md trims, etc.). Only ask when a decision is genuinely destructive or shapes product direction.
-   **replit.md upkeep**: Roll the changelog window proactively. When shipping a new release entry, demote the oldest "Recent (full detail)" item to a one-line guard-rail in the same pass — do NOT wait to be asked.

## Run & Operate

-   **Install dependencies**: `pnpm install`
-   **Run dev server**: `pnpm dev`
-   **Build app**: `pnpm build`
-   **Typecheck**: `pnpm typecheck`
-   **Codegen**: `pnpm codegen` (for API client)
-   **DB Push**: `pnpm db:push` (for Drizzle schema migrations)
-   **Required Env Vars**: `MAIL_HOST`, `MAIL_USER`, `MAIL_PASS`, `MAIL_FROM`, `SMS_API_KEY`, `SMS_SENDER`

## Sandbox quirks (Replit main agent)

-   **`pnpm install` is blocked** in the main-agent sandbox — pnpm touches `.git/config` and the sandbox classifies it as a destructive git op. To restore a missing `node_modules/@workspace/<lib>` symlink, recreate it manually with `ln -s ../../../../lib/<name> artifacts/imported-app/node_modules/@workspace/<name>`. The `strip:workspace-symlinks` script (run by `pnpm run package*` to flatten symlinks for electron-builder) is a one-way trapdoor in this sandbox — re-running `pnpm install` to restore them isn't possible from here.
-   **`git push` is blocked** in the main-agent sandbox (same `.git/config` touch classification). Ship via the GH Contents API using `GH_PAT` — PUT each changed file to the target `release/v0.7.<N>` branch on `nanvilow/scripturelive-ai`, then trigger `workflow_dispatch` on `release-desktop.yml` (workflow ID `265047930`) with **BOTH** `ref: release/v0.7.<N>` AND `inputs.tag: v0.7.<N>` (the leading `v` is mandatory). The `!cancelled()` job-condition fix for the release-desktop workflow already lives on `release/v0.7.228` (`2e73b7d` + `85d4117`) — cherry-pick onto new release branches if it isn't already there.
-   **CRITICAL workflow_dispatch `inputs.tag` MUST be set (v0.7.247 root cause #2)**: dispatching with `{"ref": "release/v0.7.<N>"}` only — without `inputs.tag` — succeeds the workflow trigger (204) and runs the Next.js + Windows installer builds to completion, but the "Upload installer" step fails with `No files were found with the provided path: artifacts/imported-app/release/ScriptureLive-AI-refs/heads/release/v0.7.<N>-Setup-*.exe`. The Resolve tag step at `release-desktop.yml` L214-229 falls into its else branch when `inputs.tag` is empty: `tag_name="${GITHUB_REF#refs/tags/}"` which leaves the full `refs/heads/release/v0.7.<N>` intact (no `refs/tags/` prefix to strip), then `version=${tag_name#v}` keeps the same string (no leading `v`), then the artifact upload glob (L445) expands to the broken path above. Electron-builder actually produced `ScriptureLive-AI-0.7.<N>-Setup-x64.exe` correctly — the build is fine, only the upload glob is wrong. **Canonical dispatch payload**: `curl -X POST .../actions/workflows/release-desktop.yml/dispatches -d '{"ref":"release/v0.7.<N>","inputs":{"tag":"v0.7.<N>"}}'`. **Operator-detectable signal**: failed run's "Upload installer" step log contains `ScriptureLive-AI-refs/heads/...` in the missing-files path → re-dispatch with `inputs.tag` set, do NOT rebuild from scratch (the artifacts on the runner are already gone, but the build is cheap to re-run — ~22 min on the windows runner).
-   **CRITICAL ship-script EXCLUDE_FILES MUST cover BOTH baked-credential files (v0.7.253 secret-scan failure root cause)**: gitignored locally but the ship-script walker doesn't honour `.gitignore` — it only respects the explicit `EXCLUDE_FILES` set. Required entries: `'src/lib/baked-credentials.ts'` (server SMTP/SMS) AND `'src/lib/keys.baked.ts'` (renderer OpenAI/Deepgram). v0.7.251 → v0.7.253 shipped real Deepgram API key into git history on three release branches because only the server file was in the exclude set. Operator-detectable signal: Secret Scan workflow goes red with `gitleaks` finding `RuleID: deepgram-api-key` (or `openai-api-key`) at `artifacts/imported-app/src/lib/keys.baked.ts:11`. **Mandatory remediation when triggered**: (1) operator rotates the leaked key in the provider console (Deepgram/OpenAI dashboard) — leaked-and-rotated is the only safe state, gitleaks-whitelisting a live key is NEVER acceptable; (2) add the missing path to `EXCLUDE_FILES` in the ship script template for future releases; (3) optionally delete the affected `release/v0.7.<N>` branches via `DELETE /repos/.../git/refs/heads/release/v0.7.<N>` — the GH Release tag + uploaded `.exe` are independent of the branch and survive branch deletion, but the leaked-key commit becomes orphaned and gets GC'd.
-   **CRITICAL ship-drift rule (v0.7.237 root cause)**: every release MUST PUT every drifted file, NOT just `package.json` + `CHANGELOG.md` + `installer.nsh` + `replit.md`. The sandbox's local working tree is the ONLY place feature/fix code lives until explicitly PUT to GitHub — there is no `git push` to discover divergence. v0.7.226 → v0.7.236 all shipped binaries equivalent to v0.7.225 with version bumps because the 4-file PUT loop missed every feature file. **Mandatory pre-ship drift check**: enumerate every file under `artifacts/imported-app/` (excluding `node_modules`, `.next`, `dist`, `src/generated/prisma-client`, `tsconfig.tsbuildinfo`, `next-env.d.ts`, gitignored baked-credentials), compute git blob SHA locally, compare against remote `main` via `GET /repos/.../git/trees/main?recursive=1`, PUT every mismatch + every local-only non-build file to the release branch. The bulk-PUT Python script in v0.7.237 CHANGELOG entry is the canonical reference. **Operator-detectable signal**: if a fix landed in source 3+ releases ago and a freshly-installed binary still doesn't show it, the FIRST diagnostic is `curl /repos/.../contents/<file>?ref=main | base64 -d | grep <fix-marker>` — NOT another reinstall, NOT a state-cleanup walkthrough.

## Architecture decisions

> Detailed historical entries live in `artifacts/imported-app/CHANGELOG.md`. The list below keeps only the **last release in full detail** plus tight one-line guard-rails for older patterns we still want future agents to respect.

### Recent (full detail)

-   **v0.7.265 — Per-code Deepgram AI-detection usage + estimated-cost tracking in admin**: New durable per-activation-code accounting so the operator sees how much audio each user (activation code) streamed to Deepgram and the estimated USD cost. **Storage** (`src/lib/licensing/storage.ts`): `deepgramUsageMs?` added to `ActivationCodeRecord` + `AdminCodeRow` (mapped in `listAdminCodes`); `deepgramPricePerMinute?` on `RuntimeConfig`; new `addDeepgramUsage(code, deltaMs)` — a SINGLE monotonic accumulator (`+=`), 30-min per-delta cap (runaway-flush guard), no-op on empty/unknown code or non-finite/≤0 delta; `applyAdminLedgerSnapshot` MAX-merges `deepgramUsageMs` so cross-device sync NEVER rolls a code's usage backward; `extractAdminLedgerSnapshot` includes it. **Telemetry path**: renderer → local forwarder `POST /api/telemetry/deepgram-usage` (`{ms}` → resolves the active code from `getFile().activeSubscription.activationCode`) → cloud accumulator `POST /api/telemetry/usage` (zod-validated → `addDeepgramUsage`). Matches the existing UNAUTHENTICATED telemetry-surface pattern (heartbeat/error/install/records/codes-last-seen are all unauthenticated) — deliberate parity, not an omission. **Renderer metering** (`src/hooks/use-deepgram-streaming.ts`): meters AUDIO-SENDING time only, NOT raw socket-open wall-clock. Marks open time on ws `onopen`, flushes accrued ms every 60s + on `onclose`/teardown, and — critically — PAUSES metering while `micPaused` (flush + null the open-mark on pause; restart the clock on resume ONLY if `wsRef.readyState===OPEN`), because `onaudioprocess` suppresses frame sends while paused so paused intervals stream no audio and must not bill. Sub-250ms deltas are dropped. **Admin** (`admin-modal.tsx`): `deepgramPricePerMinute` config (default **0.0077 USD/min**, clamp 0..10, `null` clears to default) — synced cross-device via the admin ledger (deliberately NOT in `LOCAL_ONLY_CONFIG_KEYS`). Recent Activations table gains "AI usage" (minutes) + "Est. cost" (USD) columns + a section-header total; Settings gains a "Deepgram price/min (USD)" input; admin config now hydrates on modal open (not only when the Settings tab is first shown). **Cloud (Hetzner) deploy REQUIRED**: `addDeepgramUsage` + `/api/telemetry/usage` run server-side on `cloud.scriptureliveai.com`; `deploy-hetzner.yml` auto-triggers on a `main` push touching `src/app/api/telemetry/**` (and `git reset --hard origin/main` pulls the `storage.ts` change too). Verified: full vitest **728/728** green (+5 new specs in `src/lib/licensing/deepgram-usage.test.ts`: increment / no-op-on-missing-code / non-finite-reject / 30-min cap / MAX-merge monotonicity), `tsc --noEmit` exit 0, architect review (caught + fixed a paused-mic overcount before ship). **GUARD-RAIL (accumulator is ADD locally, MAX on merge)**: `addDeepgramUsage` does `a.deepgramUsageMs = (a.deepgramUsageMs ?? 0) + add` (single accumulator); the cross-device merge in `applyAdminLedgerSnapshot` takes `Math.max(inc, cur)`. Do NOT sum on merge (double-counts every device's contribution) and do NOT replace on local add (loses prior usage). **GUARD-RAIL (meter only audio-sending time)**: any change to the metering in `use-deepgram-streaming.ts` MUST keep the `micPaused` pause/resume of `streamOpenAtRef`, and resume MUST gate on `wsRef.current.readyState===WebSocket.OPEN` so a closed-stream mark is never resurrected. `flushUsage` MUST be declared BEFORE the `micPaused` effect (it's in that effect's deps — moving it back below re-introduces a TDZ ReferenceError). **GUARD-RAIL (price-rate lockstep + sync)**: `deepgramPricePerMinute` default 0.0077 lives in the admin config route default AND the `admin-modal.tsx` `??` fallback — keep in lockstep; the key MUST stay OUT of `LOCAL_ONLY_CONFIG_KEYS` so the rate syncs cross-device. Cost math is `deepgramUsageMs / 60000 * pricePerMinute` (USD), single source of truth in the `usageMinutes`/`fmtUsageCost` helpers.
