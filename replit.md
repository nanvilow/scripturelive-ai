# Imported App

A Next.js application providing scripture-related services for web and desktop, enhancing live service experiences, and streamlining administrative tasks.

## User preferences

-   **Autonomy**: Act without asking for consent on routine decisions — always do what's better for the app. Do not ask permission for housekeeping (file trims, refactors, retry logic, dependency bumps, replit.md trims, etc.). Only ask when a decision is genuinely destructive or shapes product direction.
-   **replit.md upkeep**: Roll the changelog window proactively. When shipping a new release entry, demote the oldest "Recent (full detail)" item to a one-line guard-rail in the same pass — do NOT wait to be asked.

## Run & Operate

-   **Install dependencies**: `pnpm install`
-   **Run dev server**: `pnpm dev`
-   **Build app**: `pnpm build`
-   **Typecheck**: `pnpm typecheck`
-   **Codegen**: `pnpm codegen` (for API client)
-   **DB Push**: `pnpm db:push` (for Drizzle schema migrations)
-   **Required Env Vars**: `MAIL_HOST`, `MAIL_USER`, `MAIL_PASS`, `MAIL_FROM`, `SMS_API_KEY`, `SMS_SENDER`

## Sandbox quirks (Replit main agent)

-   **`pnpm install` is blocked** in the main-agent sandbox — pnpm touches `.git/config` and the sandbox classifies it as a destructive git op. To restore a missing `node_modules/@workspace/<lib>` symlink, recreate it manually with `ln -s ../../../../lib/<name> artifacts/imported-app/node_modules/@workspace/<name>`. The `strip:workspace-symlinks` script (run by `pnpm run package*` to flatten symlinks for electron-builder) is a one-way trapdoor in this sandbox — re-running `pnpm install` to restore them isn't possible from here.
-   **`git push` is blocked** in the main-agent sandbox (same `.git/config` touch classification). Ship via the GH Contents API using `GH_PAT` — PUT each changed file to the target `release/v0.7.<N>` branch on `nanvilow/scripturelive-ai`, then trigger `workflow_dispatch` on `release-desktop.yml` (workflow ID `265047930`) with `ref` set to that branch. The `!cancelled()` job-condition fix for the release-desktop workflow already lives on `release/v0.7.228` (`2e73b7d` + `85d4117`) — cherry-pick onto new release branches if it isn't already there.
-   **CRITICAL ship-drift rule (v0.7.237 root cause)**: every release MUST PUT every drifted file, NOT just `package.json` + `CHANGELOG.md` + `installer.nsh` + `replit.md`. The sandbox's local working tree is the ONLY place feature/fix code lives until explicitly PUT to GitHub — there is no `git push` to discover divergence. v0.7.226 → v0.7.236 all shipped binaries equivalent to v0.7.225 with version bumps because the 4-file PUT loop missed every feature file. **Mandatory pre-ship drift check**: enumerate every file under `artifacts/imported-app/` (excluding `node_modules`, `.next`, `dist`, `src/generated/prisma-client`, `tsconfig.tsbuildinfo`, `next-env.d.ts`, gitignored baked-credentials), compute git blob SHA locally, compare against remote `main` via `GET /repos/.../git/trees/main?recursive=1`, PUT every mismatch + every local-only non-build file to the release branch. The bulk-PUT Python script in v0.7.237 CHANGELOG entry is the canonical reference. **Operator-detectable signal**: if a fix landed in source 3+ releases ago and a freshly-installed binary still doesn't show it, the FIRST diagnostic is `curl /repos/.../contents/<file>?ref=main | base64 -d | grep <fix-marker>` — NOT another reinstall, NOT a state-cleanup walkthrough.

-   **v0.7.238 — Transport bar / live controls no longer vanish on splitter-up + voice "verse five / chapter twenty" route correctly**: operator escalations against v0.7.237. **Bug A (transport bar / Go Live row vanish)**: v0.7.232 stage quartet solved the intrinsic-size clipping path (aspect-ratio video frame pushing stage past `flex-1` via `width/aspectRatio`) but NOT the second clipping path — shrink-0 footer siblings (symmetry strip in PreviewCard, LiveBottomControls + VideoTransport in LiveDisplayCard) get clipped when panel height drops below `(stage_min=0 + toolbar + transport)` because they live INSIDE body's overflow-hidden region. **Fix A**: Card primitive (logos-shell.tsx L111-178) gains optional `footer?: ReactNode` prop rendered as `<div className="shrink-0 flex flex-col">{footer}</div>` AFTER body div but as section-level sibling — inside section's own `overflow-hidden` (chrome bleeding past Card border still clips) but OUTSIDE body's overflow region (body's clip rect can never hide it). PreviewCard L1320+ moves symmetry strip + Preview VideoTransport into `footer={<>…</>}`. LiveDisplayCard L2200+ moves LiveBottomControls toolbar + Live VideoTransport into `footer={<>…</>}`. The two clipping paths now have proper solutions and don't fight each other. **Bug B (voice "verse N"/"vest N"/"chapter N" not triggering)**: static analysis confirmed v0.7.235 voice fixes (`vest`, `show_chapter_n`, `detectShowChapterCommand`) ARE on release/v0.7.237 (Contents API verified) and dispatcher state binding (speech-provider.tsx L585-588) reads `useAppStore.getState()` fresh per-call. Pre-238 regex hard-coded `\d{1,3}` capture → every word-form utterance fell through to Bible-quote semantic match → low-confidence miss or unrelated cosine match → operator reports "not triggering". **Fix B**: commands.ts L940 + L1024 capture group widened `(\d{1,3})` → `(\d{1,3}|[a-z][a-z\s-]{1,40})`. New `parseEnglishNumber(s)` helper (L963) converts captured words to integers, returns null on parse failure. Range validation (1..200 verses, 1..150 chapters) runs against parsed integer regardless of source. Supports: 1..19 single words, tens "twenty"-"ninety" + ASR mis-spelling "fourty", compound "twenty one" / "twenty-one", hundreds "one hundred [and] twenty [three]" + bare "hundred". **GUARD-RAIL (footer slot is section-level NOT body-level)**: the whole point is escaping body's `overflow-hidden`. Do NOT move footer prop INTO body div thinking it'll save a wrapper — re-introduces v0.7.238 root cause. Section-level `overflow-hidden` on Card still clips chrome overflowing the Card border, visual contract preserved. **GUARD-RAIL (v0.7.232 stage quartet MUST stay even with footer slot)**: the two fixes solve DIFFERENT clipping paths — intrinsic-size (v0.7.232) vs sibling overflow (v0.7.238). They are NOT alternatives. Removing either re-exposes the other's path. **GUARD-RAIL (regex permissive, parser strict)**: word capture `[a-z][a-z\s-]{1,40}` is INTENTIONALLY permissive; parser owns vocabulary validation. Tightening regex to `(one|two|...)` would duplicate SMALL/TENS table inside regex alternation — high maintenance, easy to drift. **GUARD-RAIL (word-number + vest alternation MUST coexist)**: "vest five" is real ASR output (mishearing + word-form). Don't narrow either dimension thinking they're mutually exclusive. **GUARD-RAIL (range check AFTER parser, not inside)**: parseEnglishNumber returns literal number; range gates live at detector boundary so same parser serves future detectors with different ranges. Current gates: chapter 1..150 (Psalms max), verse 1..200 (slack for ASR mis-counts of Psalm 119:176). **GUARD-RAIL (parseEnglishNumber stays shared between verse + chapter detectors)**: keep SMALL/TENS tables in one place. Adding "billion"/"thousand" out of scope (Bibles top at 176 verses); growing parser invites top-K pollution. **Tests**: `pnpm exec tsc --noEmit` clean; regex+parser validated against 16 inputs (5 control + 11 new + 4 out-of-range rejections). **Verification cadence**: after release-desktop completes, Contents API SHA-verify `release/v0.7.238` commands.ts contains `parseEnglishNumber` AND logos-shell.tsx contains `footer?: ReactNode`.
