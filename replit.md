# Imported App

A Next.js application providing scripture-related services for web and desktop, enhancing live service experiences, and streamlining administrative tasks.

## User preferences

-   **Autonomy**: Act without asking for consent on routine decisions — always do what's better for the app. Do not ask permission for housekeeping (file trims, refactors, retry logic, dependency bumps, replit.md trims, etc.). Only ask when a decision is genuinely destructive or shapes product direction.
-   **replit.md upkeep**: Roll the changelog window proactively. When shipping a new release entry, demote the oldest "Recent (full detail)" item to a one-line guard-rail in the same pass — do NOT wait to be asked.

## Run & Operate

-   **Install dependencies**: `pnpm install`
-   **Run dev server**: `pnpm dev`
-   **Build app**: `pnpm build`
-   **Typecheck**: `pnpm typecheck`
-   **Codegen**: `pnpm codegen` (for API client)
-   **DB Push**: `pnpm db:push` (for Drizzle schema migrations)
-   **Required Env Vars**: `MAIL_HOST`, `MAIL_USER`, `MAIL_PASS`, `MAIL_FROM`, `SMS_API_KEY`, `SMS_SENDER`

## Sandbox quirks (Replit main agent)

-   **`pnpm install` is blocked** in the main-agent sandbox — pnpm touches `.git/config` and the sandbox classifies it as a destructive git op. To restore a missing `node_modules/@workspace/<lib>` symlink, recreate it manually with `ln -s ../../../../lib/<name> artifacts/imported-app/node_modules/@workspace/<name>`. The `strip:workspace-symlinks` script (run by `pnpm run package*` to flatten symlinks for electron-builder) is a one-way trapdoor in this sandbox — re-running `pnpm install` to restore them isn't possible from here.
-   **`git push` is blocked** in the main-agent sandbox (same `.git/config` touch classification). Ship via the GH Contents API using `GH_PAT` — PUT each changed file to the target `release/v0.7.<N>` branch on `nanvilow/scripturelive-ai`, then trigger `workflow_dispatch` on `release-desktop.yml` (workflow ID `265047930`) with `ref` set to that branch. Future tightening MUST preserve the ratio (and both numbers move together — change one, change the other). **GUARD-RAIL (NDI drift exemption survives the threshold change)**: drift tolerance check MUST stay gated behind `!IS_NDI`. Removing the `!IS_NDI` gate re-opens v0.7.194-class NDI freezes. **GUARD-RAIL (preview writeback at 0.25s)**: preview MUST stay 0.25s — preview does not broadcast, the throttle is just local transport UI bookkeeping. Raising preview to match live wastes update bandwidth on a local-only consumer; lowering it costs CPU without any user-visible benefit. **GUARD-RAIL (broadcast gate is module-local, NOT Zustand)**: gate MUST live in `broadcast-gate.ts` as plain mutable module state. Lifting it into Zustand would itself trip `useAppStore.subscribe` on every flip — partially defeating the suppression AND adding gate-flip POSTs to the very chatter we're suppressing. Module-local also means the Settings preview iframe (if it ever imports the same module) shares the gate naturally without cross-frame Zustand wiring. **GUARD-RAIL (window-level release listener)**: pointerup MUST be attached to `window`, not the Slider Root. Radix lifts pointer capture outside the track's hit-test on a wide drag — a Root-level pointerup would miss the release and leave the gate stuck true, silently freezing every SSE broadcast app-wide (no error, no log, no console-side feedback). Use `{once: true}`-style self-cleanup by `removeEventListener` inside the handler. **GUARD-RAIL (unmount cleanup releases gate)**: Slider `useEffect` cleanup MUST call `setBroadcastSuppressed(false)` unconditionally. Stuck-true gate is silent and total — receivers freeze with no operator-visible degradation in the operator console (which doesn't go through the broadcaster). Without this the dirty snapshot only drains on the NEXT store mutation, which can be many seconds later if the operator releases a slider and walks away — receivers would sit on stale state. The 16ms debounce exists to coalesce bursty store updates; an explicit drag-release is the opposite of bursty. **GUARD-RAIL (suppression check FIRST in schedule)**: order in `OutputBroadcaster.schedule()` MUST be `if(cancelled) return; if(isBroadcastSuppressed()) return; if(flushTimerRef.current) return; setTimeout(...)`.
