# Imported App

A Next.js application providing scripture-related services for web and desktop, enhancing live service experiences, and streamlining administrative tasks.

## Run & Operate

-   **Install dependencies**: `pnpm install`
-   **Run dev server**: `pnpm dev`
-   **Build app**: `pnpm build`
-   **Typecheck**: `pnpm typecheck`
-   **Codegen**: `pnpm codegen` (for API client)
-   **DB Push**: `pnpm db:push` (for Drizzle schema migrations)
-   **Required Env Vars**: `MAIL_HOST`, `MAIL_USER`, `MAIL_PASS`, `MAIL_FROM`, `SMS_API_KEY`, `SMS_SENDER`

## Stack

-   **Monorepo**: pnpm workspaces
-   **Runtime**: Node.js 24
-   **Language**: TypeScript 5.9
-   **Frontend**: Next.js 16
-   **Backend**: Express 5
-   **Database**: PostgreSQL, SQLite, Replit DB
-   **ORM**: Drizzle ORM, Prisma
-   **Validation**: Zod
-   **Build Tool**: esbuild
-   **API Codegen**: Orval
-   **Speech Recognition**: OpenAI `gpt-4o-mini-transcribe`, Deepgram Nova-3
-   **AI SDK**: OpenAI SDK
-   **NDI Integration**: `koffi` FFI binding to bundled `Processing.NDI.Lib.x64.dll` (NDI 6 runtime ships inside installer as of v0.7.146 — no separate NDI Tools install required)

## Where things live

-   `apps/nextjs-app`: Next.js frontend and Electron wrapper.
-   `apps/api-server`: Express API backend.
-   `packages/`: Shared utilities and components.
-   `artifacts/imported-app/db/custom.db`: SQLite database for the desktop app.
-   `artifacts/imported-app/build-resources/ndi/Processing.NDI.Lib.x64.dll`: bundled NDI runtime (v0.7.146).
-   `public/downloads/manifest.json`: Manifest for dynamic downloads.
-   `openapi.yaml`: API contracts (source of truth for Orval codegen).
-   `drizzle/schema.ts`: Drizzle ORM database schema.
-   `styles/theme/`: Theme-related files.

-   **v0.7.193-hotfix.4 — Add missing Bar Height UI control to NDI Output panel**: Operator after v0.7.193-hotfix.3 install reported "the NDI lower third settings are not working they dont apply to text" with OBS screenshot showing Esther 5:8 KJV body text rendered tiny inside a narrow bar despite NDI Typography panel set to Size=Extra Large + Ref Size=Extra Large + Ref Scale=1.20 (the hotfix.1 mockup defaults). NDI panel READ the field (`lowerThirdHeightSetting` hook L269, used to bake URL `lh` param L102 + L1222) but no UI control let the operator CHANGE it. Existing-install operators were stuck on whatever `lowerThirdHeight` their persisted state had — typically 'sm' (22%) or 'md' (33%) from before hotfix.1's NDI_DEFAULTS bump to 'lg' (35%) — with no way to migrate. Long verses (Esther 5:8 ~210 chars) in a narrow 22% bar → autofit binary search (route.ts L908-921) shrinks body text to ~30 px to fit 3 lines in `parent.clientHeight - reference.offsetHeight` ≈ 187 px → operator sees tiny text + perceives "settings don't apply". Add this audit to the pre-release smoke list. **GUARD-RAIL (B) — `lowerThirdHeight` writer lives in NDI Output panel, NOT in main Settings overlay**: this is intentional because (a) operators almost always tune bar height while looking at the NDI/OBS preview (the panel has the live preview iframe right next to it), (b) the field is shared so putting it in Settings would be just as valid but operators cluster all NDI-related controls in the NDI panel by workflow, (c) duplicating the control in BOTH places would cause confusion ("which one wins?" — they'd both write the same key, last-write-wins, but operators don't know that). Tooltips on hover are easy to miss; popover help fades quickly. Inline body-text help under the control is permanent + scannable. ANY broken link = the bug. Pre-fix this case the chain broke at step (1) — zero writers — so the operator was either changing nothing (clicking a label) or changing the wrong field (`ndiLowerThirdScale` slider instead of `lowerThirdHeight` bucket). The `user_query` two-question diagnostic (cache-refresh + lh-current-value) was the right move because it isolated the failure mode in 1 turn instead of 3+ rounds of "try this, try that." **PROCESS GR — Diagnostic `user_query` BEFORE proposing code changes saved 1+ wasted ship cycle**: pre-diagnostic candidates were (i) stale OBS cache, (ii) lh setting wrong, (iii) actual code regression. ## Gotchas

-   `persist()` operations are fire-and-forget async writes to prevent UI freezes, with retries for disk contention.
-   License state changes trigger hard page reloads; avoid complex UI interactions immediately after them.
-   NDI sender has a 60-second "linger mode" after disconnect to maintain OBS/vMix connections.
-   Renderer crashes are handled by a crash mask that attempts recovery and logs full history.
-   Auto-live confidence thresholds (current as of **v0.7.127**): explicit ≥0.60, semantic ≥0.50, suggestions 0.10–0.499, **1.25 s anti-flicker dwell**, newest-first ordering. The `source==='suggestion'` bypass in `suggestionsFor()` was REMOVED — upstream taggers must keep suggestion-tagged confidence inside the 0.10–0.499 band or the verse is dropped from the UI entirely.
-   The "Detected Verses" card separates explicit / semantic / suggested verses into three columns, each with independent auto-live decisions.
-   The cloud at `scripturelive.replit.app` MUST be redeployed from the same commit BEFORE customers update; otherwise v0.7.145+ activation cloud-fallback hits 404.
